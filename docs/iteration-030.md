# Iteration 030 — deep immutable gameplay and reference snapshots

AUD-04 is fixed for the canonical gameplay graph: GameState.Party, ItemInventoryState.Items and RoundResult.Events are ImmutableArray; optional hero mana, spellbook, skills, hero/enemy effects and known recipes are ImmutableList. Elements are immutable records/scalars. A with copy may share these collections safely; changing a collection produces a new value instead of changing the prior snapshot. Mutable working arrays in combat remain private to the transition and are converted before publication. Callers converting mutable construction buffers use copying ToImmutableArray/ToImmutableList, not a read-only wrapper over the same array.

Original spell and recipe catalogs also own immutable collections, including nested school flags, ingredient IDs/names and issue flags. Recipe inactive-pair counters use ImmutableDictionary. Synthetic recipe ingredient collections are immutable too. Source validation rejects uninitialized/default immutable arrays explicitly rather than accidentally dereferencing their backing storage. Research-only native slot models and transient recovered-rule input arrays are not canonical gameplay snapshots and were not migrated in this patch.

No save schema bump is needed: arrays remain JSON arrays, inactive-pair counts remain an object, optional absent/null gameplay collections remain null. Existing schema-1 inventory migration and schema-2 load/save behavior are exercised by the unchanged integration tests and client smoke. The C# collection API intentionally changes; callers now publish immutable values explicitly. Original numerical formulas and fixture combat behavior are unchanged.

Regression coverage reproduces the aliasing boundary: retaining and changing construction arrays cannot alter a published game; writes through IList/IDictionary are rejected; nested persistent edits and catalog with copies cannot mutate previous snapshots. Game, spell and recipe JSON roundtrips retain their data and shapes. Default required collection inputs fail with InvalidDataException.

Validation: 2,031 portable C# checks including mobile gestures; 2,038 with the private 819-item catalog; 2,032 in the spell run covering 826 metadata/power scenarios; 2,032 with 36 recipe references and in the native-flow run covering 35 unflagged original combinations. Python: 27 tests. Client builds with zero warnings/errors. Desktop fixture, mobile fixture and desktop private-catalog smoke pass. Private source data is not committed.

AUD-05 is deliberately still open: the standalone ProjectileSeriesState currently contains its own inventory snapshot. Immutability prevents mutation through aliases, but does not prevent overwriting current state with a stale flight snapshot. TOC-42 remains in progress for one authoritative inventory, in-flight reservations/version checks, atomic completion, duplicate callback protection against current state, unrelated changes during flight and deterministic complete-action persistence. No claim of a completed original actor executor or live original combat follows from this change.
