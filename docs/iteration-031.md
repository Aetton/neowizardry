# Iteration 031 — current-state projectile completion

AUD-05 is addressed at the canonical game-state boundary. ProjectileSeriesState no longer contains an inventory. Its resource lifecycle and the ordinary strike/refill helpers receive the current ItemInventoryState explicitly; completion returns a resource transaction alongside the new series counters. PendingProjectile retains only the source instance, ordinal and optional resolved aim. No native inventory slots or whole-inventory flight copies are persisted.

ProjectileExecution is the consumer of those helpers. GameState owns one Items inventory and an immutable action dictionary. Begin allocates a monotonic action ID and binds the action to a typed actor reference, item database hash and ordinary-projectile-v1 ruleset. Launch records the actual source snapshot and resolved aim without spending. Complete looks up the pending ordinal in the supplied current GameState, resolves the caller-provided actual collision target/strike inputs, and returns one state containing the resource expenditure, clamped target HP change and advanced/cleared action. It never installs launch-time inventory over current inventory. Death after launch still pays; self-hit death stops continuation. Miss, interception and armor stop still consume one projectile.

The pending source is an optimistic reservation of the entire instance. Every canonical inventory commit and save checks that the source still equals the pending source snapshot. Moving, splitting, spending, deleting or changing that instance fails atomically while in flight; unrelated inventory/actor/turn/RNG changes remain possible. Distinct actors can have simultaneous pending shots from distinct sources. A second reservation of the same source and a second unfinished series for an actor are rejected. This conservative instance reservation is not a new original-game eligibility rule; finer-grained shared-stack reservations can be introduced deliberately later.

Callbacks must be submitted to the owner's current state and commits serialized, as with other immutable Game transitions. The action ID/ordinal checked in that current state rejects duplicate, delayed and foreign callbacks. This pure API is not a mutable concurrent state store and cannot prevent a caller from overwriting newer state with an independently retained older GameState; an asynchronous owner must serialize commands or compare-and-swap the expected state. Forget removes a non-pending stopped/depleted action deliberately, while the persisted high-water sequence prevents ID reuse. Reload/refill uses the same current inventory and preserves action ID, completed ordinal and remaining allocation.

Game save schema is now 3: schema-1 aggregate inventories and schema-2 instance saves migrate without invented actions, ammunition or RNG draws. New action fields are rejected inside downgraded legacy schemas. Saved actions require the same item catalog on load; unsupported ruleset identifiers are rejected. Aim metadata is validated without re-running aim perturbation or drawing RNG. Full-state roundtrip/completion checks preserve pending source/aim, current HP/items/identity counters and RNG. These are the save contracts for this scoped executor, not a parser for original SAV/CHR files.

Original actor stats/hand policies, source accessibility and weapon/cost preparation, trajectory/collision, target defenses, penetration/damage draw plans, actor conditions, reward/XP scheduling and original initiative remain outside this boundary. Explicitly supplied inputs stay explicit. Canonical commands also enforce the existing fixture equipment save/load boundary: unsupported original ranged-hand layouts are rejected until that boundary is deliberately extended; an equipped supported source is covered by pending save/load before consumption. The Godot training round still uses labelled fixtures; no completed original combat scene is claimed. The shared-state executor can commit resolved hero/enemy collisions, including a different actor from the aim target, but does not discover collisions itself.

Regression coverage retains the existing arithmetic/lifecycle cases via a test-only context bundle and adds 48 direct canonical execution checks: unrelated split/equipment/loot/resource/actor changes, duplicate/delayed/foreign callbacks, two concurrent flights, source reservation failures, actual-target damage, actor/self-hit death, no-damage outcomes, resource depletion/removal and refill, retired identities, overflow, catalog/ruleset mismatch, schema migration and deterministic pending continuation. The test context is not a production flight or save format.

Validation: 2,079 portable C# checks including gestures; 2,086 with all 819 private original items; 2,080 in the 826 spell metadata/power scenario run and the 35 original-combination native-flow run. Python: 27 tests. Client builds with no warnings/errors. Desktop/mobile fixture smoke and the private-catalog desktop smoke (819 items, 150 spells, 36 recipes) pass. The scratch Godot executable was truncated after environment restoration; extracting the intact executable and running in the same invocation restored smoke execution. Private original data remains outside git.
