# Iteration 013 — combination rules and reference UI

Extended the executable analysis to identification, inclusive skill thresholds, two-stack minimum batches, whole-instance consumption for nonstack inputs, result quantity and destination selection. `NativeCombinations.Plan` calculates that local operation over two distinct normalized item snapshots without changing a save. Charged ingredient instances are consumed whole in this branch; this is separate from reducing an item's charges. Evidence and limits are recorded in [recipe-format.md](recipe-format.md).

Added `RecipeCatalog` with source/count validation, per-record hashes, decoded-field agreement with raw records, anomaly flag checking and database-order preservation. The Godot client loads `local/recipes.json`, `user://recipes.json` or `--recipes path`. Menu → Combination reference searches results and ingredients, displays skill gates and allows explicitly showing flagged records. Craft on an imported original item catalog opens this reference. Public previews include one invented combination reference only.

This does not execute original crafting in the game's shared-bag inventory. Native instance identity, identification/charges, output initialization, actor eligibility, progression, timing and original inventory placement are not integrated. The planner also does not implement the ordinary same-item stack merge fallback after an unsuccessful recipe attempt. Existing synthetic crafting and saves retain their behavior.

Validation: 24 Python tests, 266 C# checks including mobile gestures (267 with the private recipe catalog), warning-free client build, desktop gameplay smoke loading all 36 real references, synthetic-reference mobile smoke, search/anomaly-toggle/modal-cleanup checks, and graphical desktop/touch inspection passed locally. Windows CI generates, exports and smoke-loads the synthetic reference fixture; Linux smoke selects it explicitly. Full original data stays outside git and public packages.
