# Iteration 033 — initiative, first live original spells, monster reference import

New training parties use recovered character initiative and interleave repeated attack groups. The pure calculation is called by the same MeleeCombat executor that commits physical attacks. See [initiative evidence and scope](original-initiative.md). Explicit authored effective facts persist in schema 4; older melee saves lacking these optional facts retain their prior scheduler. They are never upgraded by inventing character statistics.

With the supported original spell catalog loaded, a new party starts with an explicitly authored level-10 Faerie Mage in its first slot. Magic offers original Frost and Energy Blast, powers 1–7, learned IDs, realm mana and cost previews. A cast replaces that actor's weapon attacks, enters the same round queue without weapon initiative, pays `baseCost*power`, rolls the imported damage dice multiplied by power, applies recovered integer Power Cast and target resistance, clamps HP and commits RNG/round/rewards atomically. Both pinned record hashes must match the independently validated original evidence; arbitrary metadata does not become an executable effect. Spell evidence validation is cached by immutable catalog identity.

This first live subset accepts **zero-risk ordinary casts only**. It is not complete original magic: risky casts/backfire side effects and costs, healing, effects, learning, skill training, general class/book/history resolution, interruption, projectile collision and original spatial targeting remain open. The Mage's book/realm skills, resolved caster/strength levels and the character opponent's level/resistances are explicit training facts. Immediate delivery and the training-room reach gate are authored scenario policies. Synthetic spells remain available in their separate sandbox.

Monster import has started with 595 source records. Python importer and C# catalog validate record boundaries, four text slots and hashes; a searchable client browser exposes the definitions. No monster field is guessed from a runtime offset. See [format boundary](monster-format.md). Original records remain local.

Validation: 3246 portable C# checks including gestures; 3269 with the original 819-item catalog; 3327 with the 150-spell catalog (including live spell casts, mana, resistance and saved continuation), plus 826 metadata/power scenarios; 3254 with all 595 monster records; 32 Python tests. Client builds with zero warnings. Headless Godot passes the original item/spell/recipe/monster catalogs, live magic UI/core, physical combat, monster browser, save/load and legacy migration; portable touch smoke passes. CI/Windows preview results are recorded in the associated issue after publishing.
