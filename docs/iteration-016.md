# Iteration 016 — live instance inventory and save migration

Cut the live prototype over to `GameState.Items`: bag, weapon equipment, combat weapon lookup, starter items, victory loot and fixture crafting now share one typed instance inventory. Removed aggregate owned stacks and duplicated equipped-definition fields from game state. Equipment moves the selected instance, retaining identity, identification, curse state and resource counters. New identities use a saved monotonic sequence. Creation and crafting pack compatible outputs before final capacity validation; rejected operations leave source items and RNG intact.

Items now selects a spare copy, displays its quantity/resource state, equips that copy and provides Split one / Merge compatible. Desktop and touch-window layouts were inspected; UI actions are included in automated Godot smoke checks. Fixture crafting still chooses eligible bag instances deterministically; original live combination execution and the larger crafting menu rework remain open.

Game save schema 2 stores typed items and their locations. The client envelope remains schema 1. `GameSaveMigration` is the only reader of old aggregate `Bag` and hero `EquippedItemId` fields. It assigns stable deterministic identities, splits legacy quantities at known definition limits, preserves equipped and spare copies, and rejects invalid/mixed or oversized data without truncation. Historical resource counters were absent: those copies migrate with zero remaining resource and no random draws or free refill. Schema-2 catalogs use documented prototype compatibility rules; schema-3 exports provide native resource kinds and limits. This is prototype save migration, not original SAV/CHR parsing.

Loading leaves the source file untouched. A failed client load blocks background autosave until a valid load or an explicit new expedition, preventing replacement of an unreadable save by fresh state. Core inventory capacity remains configurable; game defaults to a 4096-instance allocation guard, not an original or final gameplay limit.

Validation: 438 portable C# checks including mobile gestures, 445 with the private 819-item catalog; 25 Python tests; client build with zero warnings/errors. Godot smokes passed for real data (819 items/150 spell references/36 combination references), synthetic crafting and mobile controls. New smoke coverage checks actual instance selector/split/merge callbacks, client legacy-save migration, unchanged source bytes on load, and failed-load autosave protection. Original data remains private. See [architecture](architecture.md#inventory-boundary--decision-2026-10-15).
