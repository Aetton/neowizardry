# MONSTERS.DBS — first import boundary

The supplied database is 394489 bytes: a little-endian DWORD count of 595 followed by 595 records of **663 bytes**. All rows have four terminated UTF-16LE text slots, each 48 bytes, at offsets 0, 48, 96 and 144. Slot 0 contains editor-like labels (including suffixes); the other slots are preserved without assuming singular/plural or unidentified-creature semantics. Bytes following a terminator are retained, not required to be zero padding.

`python -m tools.slf monsters <DATA.SLF> --patch <PATCH.001> --out local/monsters.json` uses the existing loose/patch/base resolver. `--loose-dir` works as for the other catalogs. The importer rejects mismatched count/length, trailing/truncated records, malformed UTF-16 and unterminated text slots. JSON retains stable ordinal IDs, all four texts, raw bytes, record SHA-256, complete database SHA-256 and source provenance. Core recomputes hashes and compares all typed fields to the evidence; row IDs must match source order. Original data is private and not bundled.

Client loads `local/monsters.json`, `user://monsters.json`, or `--monsters <path>`. Menu → Monster reference searches the four native texts. This is an original-content reference browser, **not a monster combat importer**. The 485-byte runtime monster definitions in existing attack/defense research must not be treated as the 663-byte on-disk layout.
