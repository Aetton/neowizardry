# Iteration 015 — clean inventory core and isolated original research

User decision: reproduce inventory functionality on a modern instance model, without carrying original storage hacks into gameplay. `ItemInventory` provides stable instance IDs, explicit quantities/resource counters/identification/curse state, container and equipment locations, configurable capacity, property-preserving transfers, stack splits/merges, resource spending, atomic consumption/production and typed save/load. Original bytes and hashes are excluded from canonical state. `OriginalItemAdapter` converts supported original instances and returns source evidence separately; unresolved import inconsistencies are rejected.

Recovered the original stack normalization, partial/full merge return semantics, overflow partitioning and local move behavior. Those utilities and their slot snapshots live under `NeoWizardry.Core.Research`; they are not authoritative gameplay state. The research implementation refuses insufficient overflow capacity and incompatible metadata instead of reproducing original loss paths. See [item-instance evidence](item-instance-format.md#recovered-stack-helpers-iteration-015) and the [inventory boundary](architecture.md#inventory-boundary--decision-2026-10-15).

Integration remains explicit: live prototype bag, equipment and fixture crafting still use their aggregate state. The next cutover must migrate those callers and old saves together to the typed core. Native recipe actor eligibility, training/time, complete save import and the deferred crafting UX rework remain separate work.

Validation: 406 portable C# checks including mobile gestures, 25 Python tests, warning-free client build, real-data Godot gameplay smoke (819 items/150 spell references/36 recipe references) and synthetic mobile smoke. Private-data checks exercise 35 named original combinations through both local research simulation and clean inventory consumption/production with save/load. Test data for those transactions uses one of each ingredient; this does not establish actor or progression behavior. Original records and binaries remain outside public git.
