# Iteration 025 — character defense and fatigue identification

Recovered character defense producer `0x4EE9D0`: effective Speed/Stealth/Shield/Reflexion contributions, explicit active equipment, resolved natural/defensive-action flags, separate signed effects, encumbrance/fatigue categories, derived-bonus suppression and incapacitation cap. Body armor, base avoidance defense and weighted display average are independent outputs. Character hit-location selection uses the recovered 15/40/30/10/5 distribution.

Recovered the character target consumers: hit uses base plus dynamic context K; penetration uses selected body-location defense plus **two** K contributions, because `0x542FC0` calls the context-bearing base helper and the context helper again. Preserved this observed baseline without silently deduplicating it. The arithmetic effects are represented by resolved context flags, rather than guessed condition/action names.

Corrected an earlier semantic identification error: score builders read fatigue at +0x169E, not encumbrance at +0xBC9. Renamed calculation input `LoadCategory` to `FatigueCategory` and corresponding score-breakdown properties. Integer score arithmetic is unchanged. Added stamina-ratio fatigue classification with exact threshold/truncation order. Attack budgets and primary-hand equipment-load inputs retain their original meaning. Current evidence and the historical 019 report explicitly record this correction; no live save schema or prototype defaults changed.

Added `OriginalCharacterDefense`, `OriginalFatigueRules` and `OriginalDefenseAdapter`. The boundary receives an explicitly selected active set and reads signed item armor +0x62 from validated native records; native slots, bag scans and alternate weapon sets do not enter the rules. Core outputs compose with ordinary physical scores, neutral melee and post-contact projectile penetration. Actor-stat generation, class/race/action/status predicates, native character import and monster counterpart remain separate.

Validation: 1121 portable C# checks including gestures (101 added), 1128 with the private 819-item catalog, 1122 with private spell metadata/power scenarios (826 combinations, not actor eligibility). 27 Python tests pass. Client builds with zero warnings/errors. Real-data Godot gameplay and synthetic mobile smokes pass.
