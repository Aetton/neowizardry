# Iteration 032 — playable ordinary melee encounter

The default **new expedition** now runs a complete character/character melee round through recovered physical rules. The opponent is explicitly an authored Training Duelist, not an imported monster. Legacy expeditions retain the old fixture executor; loading them never adds fabricated original attributes. The menu offers **Spell sandbox** for the previous synthetic casting/crafting experiments and **Combat facts** to inspect the authored combatants.

## Executed path

Game.Attack dispatches a MeleeEncounter to MeleeCombat.Advance. It validates current inventory/catalog/ruleset, actor facts, actual equipped instances, ordinary Swing support, neutral-context eligibility and caller-resolved distance before drawing RNG. The 4.5-unit training-room reach lives in the core; the client supplies distance from its actual scene positions. It is not an original-world unit conversion or a geometry/LOS implementation.

For each eligible character, OriginalWeaponAdapter prepares the actual owned weapon. OriginalCombatRules.SingleWeapon derives BAR, attack count and maximum swings from effective attributes, skills, immutable class history and the selected weapon's initiative. AllocateSwings draws the budget per attack, including maximum=1, and applies the source bonus. Targets use OriginalDefenseAdapter, OriginalCharacterDefense.Build, weighted body location and Against. PrimaryHand and OrdinaryCharacter build hand, contact and penetration values. OriginalMeleeStrike uses the shared contact d100: natural 1–5 succeed, 96–100 miss, other rolls compare with hit and penetration. Damage dice are requested only for penetrated contact and OriginalPhysicalDamage applies strength scaling. HP is clamped and the whole round commits once with the new RNG, round, events and rewards. Dead/captive actors do not act; attacks stop when no target remains.

Contact was extracted from the existing melee resolver so the executor can decide whether damage draws are required without duplicating hit rules. Existing arithmetic regressions remain unchanged. The log includes weapon, location, outcome, HP damage and d100/hit/penetration thresholds. Hero.Power, the legacy enemy Power and legacy Speed do not drive this executor.

Both sides own real ItemInstances in the one GameState.Items inventory. The opponent has one weapon location referenced by the encounter. Victory transfers that exact instance into the shared bag and clears the opponent reference; no loot clone is created. The existing 120-point training XP pool is divided once among eligible survivors. This is scenario reward policy, not recovered original progression.

## Authored facts and supported scope

MeleeCharacterFacts and MeleeEncounter store immutable, explicit effective attributes, strength, class history, combat/weapon skills, stealth and body protection. The supplied training hero has level-10 Ninja history, STR/DEX/SPD 80, INT 50, SEN 70, combat/weapon skill 80 and stealth 20. The opposing character shares the authored class, uses lower effective attributes/skills, 48 HP and authored body protection 18 in each zone. This protection is a supplied scenario defense input, not an imported armor loadout or a claim to original character generation. These values are visible in Combat facts.

The training factory creates new owned weapon instances, selects eligible ordinary Swing weapons from the catalog and equips the party. A built-in source-validated synthetic Practice sword catalog permits startup without private game data. CI's authored demonstration catalog now has source-backed native fields and broad training race/profession masks so parties 1–8 can use it. Private original catalogs are unchanged and remain outside git; their actual equipment restrictions are honored when selecting the new scenario's weapons. An explicitly requested catalog that fails to load is not silently substituted.

This first slice is ordinary single-weapon Swing with free offhand, neutral fatigue/encumbrance/effects and context counter zero. Counter zero is an authored context, not an assertion that swing index is the original repetition counter. Low untargeted scores requiring unresolved fumble/redirection, unsupported/resource/spell-use weapons, negative/extreme swing bonuses and synthetic effects are explicit command denials. Unarmed state is saveable; it requires equipping a supported weapon before attacking. Imported item procs, critical/target-specific effects and armor-slot derivation are not executed. An imported weapon is not a claim that every property of that item is implemented.

Character creation and effective-stat producers, monster import/AI/monster strike execution, original initiative/formation/targeting, stamina/conditions, ranged delivery, original magic and original combinations remain open. Scenario ordering uses effective Speed with a stable tie-break; target selection picks the first living free hero. Dice remains the saved prototype RNG, including the authored location/contact/damage scheduling, not original-runtime RNG parity. Synthetic spells are kept in the separate sandbox rather than applying fixture rounds inside a restored encounter.

## Persistence and validation

Game save schema is 4. Schemas 1/2 migrate their prior inventory format, and schema 3 preserves its pending projectiles and high-water IDs; all retain legacy combat with Melee=null. New melee metadata inside an older schema is rejected. Restored encounters persist actor facts, opponent item ownership, item database hash, ordinary-character-duel-v1 ruleset, HP, rewards and RNG. Loading requires the correct catalog and supported ruleset. New melee and standalone projectile executors cannot be mixed accidentally in one encounter yet. Unarmed and completed-victory saves remain valid. Existing source-protection/atomic autosave behavior is retained.

Validation: 2,188 portable C# checks including gestures, 2,211 with the private 819-item catalog, including restored rounds and persistence for parties 1–8 using original owned weapons. Spell metadata and native combination runs each pass 2,189 checks (826 spell/power scenarios; 35 unflagged original combinations). Python: 27 tests. Client builds without warnings/errors. Desktop fixture smoke reaches the actual Attack button/restored resolver and Combat facts UI; mobile smoke reaches restored combat before background save/load. Private-catalog smoke passes with 819 items, 150 spell references and 36 combination references. Legacy synthetic spell/effect/crafting UI regressions remain exercised explicitly.

TOC-41 remains in progress: this is a playable ordinary character duel and an executor seam with explicit facts, not full original gameplay or an original monster encounter. Next work should supply original actor/hand/state producers and an opponent backed by actual monster definitions/attacks, extending the same current-state boundary rather than returning to disconnected formula accumulation.
