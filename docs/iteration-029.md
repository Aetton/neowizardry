# Iteration 029 — catalog integrity and reusable item rules

First defect package from the archive/code audit, addressing AUD-02 and the repeated-decoding part of AUD-03. Original numerical formulas and live fixture combat are unchanged.

Item imports now compare every exported record-backed field with the 269-byte evidence, including signed damage constant, initiative, to-hit and the full signed DWORD bonus-swings field. Native amount/stack fields retain their own validation. Schema 2 remains supported without fabricated source bytes. Spell imports compare names, cost/level, realm/range/target/usability, all four school bytes, duration fields and damage fields with the 704-byte record. Unknown values are preserved when actually present in the source. Spell descriptions have independent database provenance and are not authenticated by a spell-record hash; record IDs likewise are external indices rather than embedded fields.

ItemCatalog.Items is now ImmutableArray. Each catalog identity owns a lazy validated frozen ID index and frozen inventory-rule dictionary. A `with` copy receives its own validation/index/rules and cannot inherit stale results. Warm inventory operations validate changing game state and instances, without scanning, hex-decoding or hashing the whole source catalog. NativeItemFields separately compiles armor, spell-use and retain-empty capabilities once; armor preparation, projectile expenditure and refill consume those semantic values. Cache lookup still checks the supplied record hash, including after a prior successful validation. Raw records/provenance remain import evidence and do not enter canonical owned items or inventory saves.

Synthetic native fixtures now encode their actual typed fields instead of attaching mostly zero source records to unrelated prototype definitions. Regression checks cover field-only tampering with an unchanged valid hash, rejection at the inventory boundary, immutable collection ownership, catalog-copy/cache isolation, shared concurrent reads, JSON compatibility and source-backed unknown spell values.

Validation: 1,999 portable C# checks including gestures; 2,006 with the private 819-item catalog; 2,000 with the private spell catalog (826 metadata/power scenarios); 2,000 in the native-flow run covering 35 unflagged original combinations. Python: 27 tests. Client builds without warnings/errors. Desktop and mobile fixture smokes pass; private-data desktop smoke passes with 819 items, 150 spells and 36 recipe references. Private source catalogs/assets stay out of git. These checks establish import and runtime preparation, not original-game actor/effect execution or mobile-device performance.

TOC-40 remains in progress: a broader unified content set/evidence sidecar and immutable spell/recipe ownership are still to be completed. TOC-41/42 track the original actor/action executor, deep game-state snapshots and authoritative in-flight inventory. No claim that those audit findings are fixed by caching item definitions.
